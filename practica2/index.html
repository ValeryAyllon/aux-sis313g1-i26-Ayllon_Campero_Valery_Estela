PRÁCTICA N2 – GIT, GITHUB Y HTML


Preguntas y Respuestas sobre Git y GitHub

  1. ¿Qué es Git y cuál es su función principal dentro de un proyecto de desarrollo?

    Respuesta: Git es un sistema de control de versiones distribuido. Su función principal es registrar y administrar los cambios realizados en el código fuente a lo largo del tiempo, permitiendo revertir estados anteriores, llevar un historial detallado y trabajar colaborativamente sin sobrescribir el trabajo de otros.

  2. ¿Cuál es la diferencia entre Git y GitHub y qué función cumple cada uno?

    Respuesta: Git es la herramienta de software local que gestiona el historial y control de versiones en tu computadora. GitHub es una plataforma en la nube que aloja repositorios de Git, permitiendo respaldar el proyecto en línea y colaborar de forma remota con otros desarrolladores.

  3. ¿Qué pasos se deben seguir en Git para guardar los cambios realizados en un proyecto y crear un commit?

    Respuesta:

    • git status (opcional): Verifica los archivos modificados.
    • git add . (o el nombre del archivo): Añade los cambios al área de preparación (Staging Area).
    • git commit -m "Mensaje descriptivo": Guarda la captura/estado de los cambios con un mensaje explicativo.

  4. ¿Qué comandos se utilizan para conectar un repositorio local con un repositorio de GitHub y posteriormente subir los cambios? Explique brevemente la función de cada uno.

    Respuesta:

    • git remote add origin <URL_DEL_REPOSITORIO>: Vincula el repositorio local con el repositorio remoto de GitHub asignándole el nombre alias "origin".
    • git branch -M main: Renombra la rama principal a "main" asegurando compatibilidad con el estándar actual.
    • git push -u origin main: Sube la rama local "main" y sus commits al servidor remoto "origin", estableciendo el enlace predeterminado para futuros empujes.

  5. ¿Qué es una rama (branch) en Git y en qué situaciones puede ser útil trabajar con una rama diferente a main?

    Respuesta: Una rama es una línea independiente de desarrollo dentro del proyecto. Es útil para desarrollar nuevas funcionalidades, corregir errores o experimentar con código sin alterar la versión estable que se encuentra en la rama principal (main).

  6. Explique el proceso para crear una nueva rama, realizar cambios en ella y posteriormente subir esa rama a un repositorio de GitHub.

    Respuesta:

    1. Crear y cambiar a la nueva rama: git checkout -b mi-nueva-rama (o git switch -c mi-nueva-rama).
    2. Realizar las modificaciones en el código.
    3. Guardar los cambios en el historial local: git add . y luego git commit -m "Nuevos cambios".
    4. Subir la nueva rama a GitHub: git push origin mi-nueva-rama.

  7. ¿Qué es un conflicto en Git y qué pasos se deben seguir para resolverlo antes de combinar los cambios de una rama con main?

    Respuesta: Un conflicto ocurre cuando Git no puede combinar automáticamente dos ramas porque se realizaron modificaciones distintas en la misma línea de un mismo archivo. Para resolverlo se siguen estos pasos:

    1. Intentar la fusión (git merge nombre-rama).
    2. Abrir los archivos afectados señalados por Git y elegir manualmente qué código conservar (editando las marcas <<<<<<<, =======, >>>>>>>).
    3. Guardar los cambios corregidos.
    4. Añadir los archivos resueltos: git add .
    5. Finalizar la fusión creando un commit de resolución: git commit -m "Resolución de conflictos".
